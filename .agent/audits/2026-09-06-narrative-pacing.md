# 叙事阶段与战斗篇幅提示评估

版本：2026-09-06.2。采用 Prompt Engineer 的需求—设计—案例评估—迭代—部署流程。

## 目标与最终行为

角色仍是 D&D 主持人。任务是按已发生的事件顺序完成叙事；规则结算与玩家决定权保持原有边界。

- 全程剧情：正常长度偏好。
- 剧情转战斗：保留原总长度目标，充分呈现进战前铺垫；战斗部分按信息量决定详略。低于下限时，编辑优先补足前面的剧情。
- 从战斗开始：可低于正常剧情下限，重要交锋仍可展开数段；最大长度仍有效。
- 卡片着色与文字篇幅分别计算；不新增“剧情段/战斗段”显示标签，也不设置固定短句或段数上限。

## 最终提示

完整角色、工具约束与格式定义位于 [prompts.py](../../backend/prompts.py)。以下为新增篇幅策略，当前阶段还会由 `narrative_pacing_context` 在模型调用前提醒：

```text
叙事篇幅与节奏：
- 按事件发生的阶段安排详略，消息卡片被标为战斗不代表整条正文都要缩写。
- 进战前仍按玩家的正常剧情偏好写清场景、对话、探索过程与冲突如何发生；进入战斗后不要在最终回复中丢掉这段铺垫。
- 战斗允许低于正常剧情的最低字数，但这是可选的篇幅自由，不是短文目标或只写结算摘要的命令。有值得描写的事件时，可以接近正常剧情篇幅。
- 普通交锋写清动作、对手反应及可见后果即可；关键命中、险境、法术表现、掩护运用与人物间的重要反应，可用完整段落呈现动作的因果、触感与变化后的局面。
- 展开已有材料中的动作路径、声音、触感、姿态和情绪；姿态反应不应改变战术站位。不额外添加新道具、物品损坏、NPC撤离或未结算的击退来制造戏剧性。
- 补足剧情篇幅时推进已发生的观察与对话层次，不反复复述同一事实、重复说明“不知道什么”，也不反复提醒“危险仍在”。
- 每段描写应增加可感知的信息或帮助玩家理解局面。保持已结算事实与行动次序，不能为写得精彩而增添伤害、位移、条件、隐藏情报或替玩家作决定。
- 在下一位玩家控制角色行动前停住事件推进。这个边界不限制充分描写已经发生的战斗；留下当下可观察的局面，而不是一句数字播报。
- 不规定每次攻击固定几句、不以最短为目标、不用重复气氛凑字数。遵守最大字数；不要解释篇幅策略或输出“剧情段/战斗段”等编辑标签。

独立风格示例（只示范详略，不是本局事实，不得复制人物、场景或结果）：
- 剧情转战斗：先写旅人递来湿透的路引、交谈中的迟疑及门外脚步如何打断对话，再顺着冲突进入交锋；不能只写“交谈完，战斗开始”。
- 重要战斗：若已结算事实是“敌人攻击未命中，守住身后的门”，可写刀锋擦过护手的震感、敌人收刃时仍封住门口的姿势；不能为增强戏剧性再加一次攻击、击退或伤口。
```

长度编辑器同步遵守混合阶段边界，移除了“字数是唯一验收标准”的旧表述；事实与叙事节奏优先。

## 测试与观察

采用相同的四份合成已结算事实，旧提示在默认模型上作基线，新版分别在默认模型与 Astra 上评估。每个组合单次生成；字数为去空白字符数，表中是未经长度编辑器处理的原始正文。不能把字数变多视为质量自动提升。

| 案例 | 旧版 Terra | 新版 Terra | 新版 Astra |
| --- | --- | --- | --- |
| 剧情转战斗 | 331 字 / 4 段 | 523 字 / 5 段 | 755 字 / 7 段 |
| 重要战斗 | 307 字 / 4 段 | 254 字 / 4 段 | 298 字 / 5 段 |
| 普通交锋 | 154 字 / 2 段 | 119 字 / 2 段 | 104 字 / 2 段 |
| 纯剧情、无新行动 | 67 字 / 1 段 | 113 字 / 2 段 | 86 字 / 2 段 |

- 新版 8/8 输出保留全部指定场景/角色锚点，8/8 没有发起额外工具调用；逐段检查了进战前内容、已结算动作次序与交还玩家决定权。
- 混合场景在两个模型上均先写对话、木牌与冲突出现，再进入交锋。重要战斗保留连续动作、可感知反应与当前局面；普通交锋不为达到剧情下限而扩写。
- 初版对比发现环境细节随意补充、重复解释未知信息的问题，第二版加强了已知材料边界与信息密度要求；这不意味着模型已完全消除这些倾向。
- 默认模型混合场景原始输出仍低于 600 字目标，故不能只依赖提示词。实际 LangGraph 混合回合验收完成：88.7 秒、455 字，原下限 450 保留，卡片仍为战斗类型，trace 的 `pacing_scope=mixed`；真实工具结算后交还玩家。
- 程序回归 353 项，352 通过、1 项默认跳过；相关回归见 [test_narrative_pacing.py](../../tests/test_narrative_pacing.py)。没有前端或 API schema 修改。

## 使用与限制

- 默认运行模型未改变；合成评估分别使用 `gpt-5.6-terra/high` 和 `gpt-6-astra/high`。测试通过现有 Codex CLI 适配层请求，未新增温度配置。
- 核心评估是叙事阶段、信息分配、事实与行动边界，未宣称文学质量达到某个准确率。少量样本不能代表所有战役；默认模型仍可能补充未提供的场景细节，Astra 偶有重复说明。
- 混合回复保留的是整条原长度目标，没有硬性规定战前部分必须单独达到同样字数。战前内容的充分性由提示与编辑策略保证，不靠不稳定的段落分类器推断。
- 只使用合成场景。可复查隔离副本 `output/combat-control-fix/output_pacing_eval.py` 和 `output_pacing_native.py`，运行前先确认副本与根代码一致。
