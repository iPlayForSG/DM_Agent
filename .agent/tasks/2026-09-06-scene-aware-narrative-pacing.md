# 按叙事阶段调整战斗篇幅

Status: completed
Updated: 2026-09-06

## Goal

按 Prompt Engineer 工作流调整提示词及长度后处理：进战前的剧情保留正常描写，战斗部分可按事件分量详略变化，避免把允许简略变成强制简短。

## Scope

- 只调整叙事与长度策略，不改变骰子、行动次数、玩家交接和卡片颜色。
- 区分全程剧情、全程战斗、剧情转战斗；混合回复不能因战斗标记而整段豁免最低长度。
- 保留既有未提交修改，用隔离副本和合成案例验收。

## Decisions

- 战斗卡片是展示类型，不能直接决定整条正文是否适用长度偏好。
- 混合回复保留原总长度目标，扩写优先补足进战前的场景、对话和行动过程，不把缺失字数转嫁给战斗。
- 停在下一玩家决策点是动作权限边界，已结算的战斗仍可充分描写。

## Evaluation

- 合成案例：探索后突发战斗、值得展开的关键战斗、普通短促交锋、纯剧情/无新增行动。
- 检查事实一致、进战前铺垫、战斗描述的信息量、玩家交接、无填充或元话术；字数只作观察指标，不能把短当作质量代理。
- 比较旧提示与新提示，在已获准的本机 Codex CLI 上验证默认模型及另一模型版本。记录模型、字数、耗时、评分与限制。
