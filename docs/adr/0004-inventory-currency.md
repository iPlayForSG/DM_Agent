# ADR-0004：实际钱币统一使用物品栏记账

Status: Accepted
Date: 2026-09-08

## Context

旧角色以独立整数gold_gp保存金币，银币奖励却进入库存，导致财富存在两处不一致的来源。用户明确选择全部金钱在物品栏管理。

## Decision

- 角色持有的钱币以inventory中的currency项为唯一事实源，统一CP/SP/EP/GP/PP名称及数量，不再持久化独立gold_gp。
- 确定性货币工具进行收入、支出与必要找零；价值运算使用整数铜币。余额不足时整个操作保持原状态，不自动出售或兑换收藏品、钱袋和贵重物品。
- Character.currency_inventory_version控制旧输入迁移：将旧金币余额添加至原有钱币库存，再移除旧余额字段。再次读取、保存及剧情回退不会重复添加。
- 读取旧文件只生成兼容的内存对象，后续正常保存才写入新表示；游戏、角色模板和rewind snapshot使用同一角色schema转换。
- 创建角色的初始金币预算仍可作为目录配置存在，实际剩余钱币写入库存。人物卡不另列财富数值。

## Alternatives considered

- 独立多币种钱包：可实现但不符合用户选择，也会继续产生钱包与实物库存的边界。
- 用浮点金币保存总值：会丢失持有面额，且引入小数精度问题。
- 仅改变前端展示：无法修复收入、支出与回滚所依据的事实来源。

## Consequences

货币与其他物品共享持久化及净变化叙事，但支付拥有独立的余额校验和找零逻辑。旧客户端应刷新以使用库存字段；未提供明确面额的特殊钱币仍视为普通实物。

## Validation / follow-up

合成回归覆盖迁移幂等、旧文件只读加载、模板与rewind、建卡重复预览、五种面额、找零、余额不足、暂停写守卫与失败回合回滚。真实模型已验证19金币6银币支付7银币后剩余18金币9银币。
